# CounterLab 使用指南

这份指南说明已经实现的领域规则和工作台流程。按钮名称来自当前组件；最终浏览器验收仍在进行，本文不把尚未检查的交互写成已通过。

## 第一次实验

先按 [启动说明](REPRODUCIBILITY.md) 启动本地服务。没有模型密钥也可以完成以下计算流程。

建议从「区间调度」页签开始：在「策略预设」选择规则，通过「编辑实验输入」修改并「应用输入」，然后点击「运行当前实例」。确认反例后选择「缩减这个反例」，修改规则后通过「对比修正前后」做回归。需要直接查看完整存档时，可用「导入」打开 [区间示例](../examples/interval.counterlab.json)、[背包示例](../examples/knapsack.counterlab.json) 或 [图路由示例](../examples/graph.counterlab.json)。这些文件是已经执行过的固定样本，导入会重算证据，不代表本次刚完成了一轮新搜索。

## 选择领域与目标

| 领域 | 问题与约束 | 内置反例 |
| --- | --- | --- |
| 区间调度 | 选择互不重叠的半开区间 `[start,end)`；端点相接允许。目标可选最大收益或最多任务，二者不同。 | A 占 `[0,4)` 收益9；B 占 `[0,2)` 收益6；C 占 `[2,4)` 收益6。收益优先选A得9，B+C得12。 |
| 0-1 资源分配 | 整数正重量、非负价值、固定容量；每件最多一次，不能拆分。 | 容量10：A重量6价值13，B和C各重量5价值10。密度优先选A得13，B+C得20。 |
| 非负权图路由 | 指定有向/无向、起点、终点与非负整数边权；当前不支持自环和重复端点连接。 | 局部选较短的第一条边，可能得到总长11；另一条完整路径总长6。 |

输入规模上限分别是 16 个区间、18 件物品、12 个图节点和 80 条边。具体数字范围见 [已知边界](KNOWN_LIMITS.md)。区间的「最早结束」策略在最多任务与最大收益目标下不能混为一谈；背包的价值密度也不能当作 0-1 问题的最优保证。

## 写清策略

策略包括算法、评分表达式、升降序和平局规则。评分只决定支持该评分的贪心/局部策略的排序；精确动态规划和 Dijkstra 使用各自确定的求解过程。

| 领域 | 可用评分字段 | 示例 |
| --- | --- | --- |
| 区间 | `start`、`end`、`duration`、`value` | `value / duration`，按单位时间收益排序 |
| 背包 | `weight`、`value` | `value / weight`，按价值密度排序 |
| 图 | `weight` | `weight` 升序，局部选择当前最短邻边 |

表达式支持数值、括号、`+ - * /`，不支持函数调用、条件表达式、脚本和任意代码。评分使用精确有理数，避免用浮点近似决定密度平局。`value` 平局规则优先较大值，其余数字平局规则优先较小值；最后按对象 ID 升序稳定排序。

表达式中的分母为零会报错。这不是「策略没有反例」，也不会被计作一次成功通过。图的局部策略不回溯，不重复访问节点；选错分支后可能陷入死路。

## 执行与理解结论

每次执行都会重算候选策略、精确参照和独立核验，再产生实际轨迹。

- **已验证反例**：候选结果不如可行的精确参照，或图中存在到终点的路径而候选没能到达。
- **当前实例通过**：只说明这个输入没有展示策略失败，不能推广到所有输入。
- **输入/计算无效**：规则或输入不合法，或结果没有通过独立核验；不能据此形成正确性结论。
- **搜索未完成**：取消、超时或异常中断；不能解释为不存在反例。

对区间和背包，收益/数量越大越好；对完整图路径，代价越小越好。图的两个特殊状态要分开：候选「未到达终点」可能是策略失败；参照确认「目标不可达」说明这个图没有可行起终点路径。不可达的数值占位0不代表存在零代价路径，候选死路也不适合显示一个普通路径长度差。

双轨中的每一步来自真实事件。两种算法的同一步号不一定处理同一个对象，所以首次选择不同只是观察，不是因果证明。

## 搜索新的反例

设置种子、样本预算和规模，再点击「搜索反例」。相同引擎版本、策略和生成参数得到相同样本序列；耗时可以变化。搜索遇到首个独立核验的反例时停止，支持取消。

当前每次最多 2000 个随机样本，生成数值上限最多100。手工输入的合法数字范围更大，因此这不是整个手工输入空间的穷尽检验。结果为「未找到」时，应一起看实际检查数、种子和预算。

改变种子是新一轮采样；修改评分、方向或目标则是在检验另一项策略主张。不要用旧策略的通过记录证明新策略正确。

## 缩减反例

只有重新验证仍成立的反例才能缩减。程序会尝试删除对象或降低数字，每个接受步骤都重新验证输入合法性、解的可行性和原来的失败类别。

缩减列表保存实际接受的步骤，可以检查前后输入。数字变小但对象数量没变也是有效缩减。图的「陷入死路」不会被悄悄改成「能够到达但路线更长」来冒充同一问题。

最多尝试4000次。完整操作轮次结束后，「局部不可再缩减」只针对程序提供的删除、取合法最小值、折半和减一操作；它不是全局最小反例证明。取消或达到预算时只保留已缩减结果。保存/导入时会重验缩减链，但不会重新执行整次最小性搜索，因此历史存档只声明「已缩减」。

## 修改与回归

保留修改前策略，再用修改后的策略比较：原输入、最多20个已保存的同领域历史反例，以及设置数量的独立生成样本。最多100个生成样本，加上原例和历史，总共最多121行。

每行都会执行前后策略，重新计算「改善」「退化」或「不变」。图中从死路变成完整路径属于改善；两次都陷入死路不会因不同的部分路径长度被误称改善。汇总是这些样本的比较，不是对所有未来输入的保证。

若只修好了原例却在历史例上退化，应继续检查策略适用条件，而不是仅看改善行数。没有保存的历史输入不会被虚构成已经检查过。

## 保存、版本与导出

给实验命名并点击「保存实验」。输入或策略改变后再次保存会增加修订；只修改标题不会新增算法版本。「实验档案」用于打开存档，「版本与复验」用于查看保存的修订。已经保存的修订保留当时的输入、策略和重新计算的结果。自动草稿属于当前浏览器；需要持久化、导出和历史回归的记录仍应明确保存到本机数据库。

领域切换分别保留三个领域的草稿；重复点击当前标签不会重置实验。「新建实验」明确创建当前领域的新草稿。自动保存也保留尚未写完的表达式，刷新后仍可继续编辑；这种草稿不被当作可执行的正确策略，运行时仍需通过校验。

JSON 实验包包含输入、策略、执行器版本、真实结果、历史及校验和。导入时不仅检查文件结构与校验和，还会重新计算数值、核验版本和缩减链。版本不兼容时拒绝静默迁移。校验和是改变检测，不是数字签名，也不证明作者身份。

「HTML报告」用于离线阅读输入、规则、结论和执行轨迹；「实验包」导出 JSON，用于完整数据重放。它们不等同于比赛所需的最终 PDF 或演示视频。

默认数据位于 D 盘应用目录 `.runtime`。关闭服务后再备份整个数据目录；不要把正在使用的数据库文件当作可任意拆开的普通 JSON。单实验最多200个修订，接近16 MiB的体积上限时会明确拒绝保存，已有数据保持不变。

## 可选 AI 提案和解释

按 README 在本机 `.env` 配置官方地址、模型和密钥后重启服务。自然语言应说明领域、优化目标与排序想法，例如「背包中先考虑单位重量价值较高的物品，放不下时跳过」。

点击「生成策略提案」后，模型返回策略、解释和假设；先检查是否表达了自己的意思，再「确认应用策略」并运行程序。模型可能提出错误规则，这恰好可以由反例实验检验。「AI解读本次证据」只解释重新验证过的实例，仍可能出现文字错误，数值事实以程序输出为准。

未配置、认证失败、超时或格式不合法都会明确报错；本地实验可以继续。每次服务会话最多100次模型请求，单次输出预算1800 token、30秒超时，费用以自己的官方账户为准。不要把密钥粘贴到策略、实验标题、导出文件或开发记录。

## 遇到问题

| 现象 | 检查方式 |
| --- | --- |
| 浏览器连不上 | 确认启动窗口仍在运行，并使用其中实际显示的端口。 |
| 页面提示构建缺失 | 源码目录先 `pnpm build`；便携版需完整解压。 |
| 不允许的数据目录 | 检查应用和 `COUNTERLAB_DATA_DIR` 都在 D 盘，路径没有指向其他位置的链接。 |
| 修改后结论没更新 | 重新运行当前输入/策略的评估，不沿用修改前结果。 |
| 搜索被取消或超时 | 查看任务状态；这是未完成，可减小预算或重新运行。 |
| AI 不可用 | 检查本机配置和账户；先用手工规则完成离线实验。 |
| 导入失败 | 检查完整文件、执行器版本、校验和与体积，不手工改结论字段来绕过验证。 |

更多边界见 [已知限制](KNOWN_LIMITS.md)，复现方法见 [启动和复现](REPRODUCIBILITY.md)。
