# 本机启动生命周期修复

用户反馈「我为什么打不开这个网站」。实际检查 `127.0.0.1:4317` 无监听进程，健康接口和页面均被拒绝连接。此前启动器同步执行 Node，依赖临时开发终端，不能据一次会话内成功检查宣称跨会话持续运行。

修复：新增 `scripts/background.ps1`，使用 Windows `Start-Process -WindowStyle Hidden` 启动独立进程，D 盘日志记录输出，健康检查通过才返回就绪地址。端口由与服务器相同的 `.env` 和环境解析，密钥不打印。进程记录保留 PID、可执行路径与创建时间；停止时匹配身份，避免 PID 复用误杀。进程控制不写系统服务、注册表或开机任务。

本机工作区入口沿用已验证发行包内 Node、源码私有 `.env` 及原数据库。发行 ZIP 保持原校验和，源码提供新的独立后台入口；旧 ZIP 前台入口按说明保持窗口打开仍然有效。

实际验证（Windows PowerShell 5）：

- 启动命令完成并退出；另一次独立命令确认 Node 父进程已不存在，但 Node 仍监听 4317，健康检查通过，首页 HTTP 200。
- 真实 Chromium 加载应用、执行区间实验、定位时间轴；页面脚本错误0，axe违规0，手机页面宽度390与视口相同。
- 停止已记录的 Node 后端口关闭；重新启动生成新 PID，健康检查重新通过。
- 构造可执行路径不匹配的进程记录，停止动作明确拒绝，原进程仍存活。
- 重复启动复用已运行服务，不生成第二个实例。重启电脑后仍需再次启动，不宣称开机自动运行。

此次新增检查只针对启动生命周期与可访问性，没有重复宣称全应用重新完成一次全部测试。所有主动创建和修改均在 D 盘。
