## 1. 意图边界与可信执行

用户原始要求包括「质量优先」「技术选型你来定，主题方向你来定」及「最好你找的选题在我交之前需要的测试人员规模不要很大」。因此产品选择可用独立计算客观验证的策略实验问题，并明确不以真人教学效果提升作为未经验证的卖点。

真实实现：以受限表达式表达可编辑策略，三个领域共用类型契约；运行用户输入，不执行模型生成代码。独立 Python 程序枚举 960 个实例，对照产品数值；引擎测试另外检查相等值、零权重、最大数值、不可达、伪造证据和固定种子。

实际修正：独立代理复核发现 API 的收益上限受旧 Zod 约束叠加影响，合法 100000 被拒绝；后端修复并增加边界测试。没有把未观察到的问题写成「经历」。

对应提交：`50bd389`（类型/接口基线）、`023ddcf`（引擎）、`22f5c26`（后端和边界修正）。详情见 [引擎记录](engine-development.md)、[后端记录](server-development.md)、`tests/oracle.py` 和 `tests/server.test.ts`。

## 2. 搜索、缩减、版本与重放

用户授权「按开发方案开始全流程开发……开发过程及时提交到GitHub」。方案先进入仓库，随后引擎、后端分别提交。搜索从真实种子生成实例，每个反例重新检查；缩减必须保留同一失败类型，修改后对原例、历史反例及独立保留样本回归。

实际复核暴露并修正：图策略死路的数值占位 0 不能被当作改善；排列顺序改变不能冒充缩减；早停找到反例时任务进度需要最终刷新；大图 121 行回归记录超过原 4 MiB 限额，导致合法实验无法保存。后端把受控包大小提高到 16 MiB，并添加完整保存/导出/导入重算测试。

## 3. 模型与视觉进入真实产品

用户原始要求：「前端界面的复杂界面你用你的image-2生成逼格高一点的，不要用简单的图形拼接」。用户又明确允许内置工具在指定 C 盘生成图片目录新增本次图片。实际生成原创工作台参考图和横幅，复制到 D 盘仓库；参考图内的示意数字不作为运行结果。

模型接入所需平台不能猜测。用户明确回答「DeepSeek 官方平台（api.deepseek.com）」后，核验官方可调用模型并配置本地忽略文件。接口仅将模型结果作为待确认提案，后端进行受限契约检查。

真实联调：2026-11-15 两次官方 `deepseek-flash` 请求完成策略转换和实验解释，合计输入 971、输出 529 token，耗时约 5.157 秒。官方接口显式关闭思考模式，防止有界 JSON 任务的输出预算被推理占用；其他兼容服务不附加该字段。此测试不代表任意模型文字永远正确。

对应提交：`1667bc7`（视觉素材）、`22f5c26`（模型适配）、`ab5a3d4`（完整界面）、`240bd3c`（实际恢复与证据缺陷修复）。2026-11-16 又通过实际工作台完成两次官方请求，输入972、输出419 token，耗时5.977秒，提案确认与解释渲染均通过。复核发现领域切换丢失草稿、旧解释残留、节点/边同名高亮混淆、任务404锁定以及未完成表达式恢复问题，分别加入真实回归测试。最终92项单元/API测试、14项完整浏览器测试通过。
