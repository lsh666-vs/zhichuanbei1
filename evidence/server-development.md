# 本地服务、证据与任务边界验证

日期：2026-11-15。记录对应实际开发与测试；不是模拟用户对话。

## 实现与决策

- Fastify 服务只监听 `127.0.0.1`。API 校验 Host 和 Origin，避免恶意网站及 DNS 重绑定读取或改变本地实验；Vite 的本机来源正常使用。API 禁止缓存，统一输出可理解的错误，不返回内部堆栈。
- SQLite 保留实验、策略与输入修订、每个修订对应的重新计算结果，以及任务状态。Windows 上数据库路径必须位于 D 盘；所有开发缓存和测试目录通过 `scripts/env.ps1` 指向 D 盘。
- 改标题不新增修订；策略或输入改变才新增。旧修订保留原来的输入与结论。旧版没有输入快照的实验包仍能导入，但不能凭空重建其历史输入。
- 保存、导入、AI 解释及缩减入口都重新运行确定性引擎，不采信客户端传来的执行轨迹、目标值、反例标记或回归汇总。版本快照同样重算。
- JSON 实验包使用稳定键排序和 SHA-256。校验和用于发现文件改变，不是作者身份认证；即使重新计算了正确校验和，伪造的数值也会被引擎替换。执行器版本不匹配时拒绝静默迁移。
- 搜索的统计历史无法通过单个反例重新证明，因此保存时明确附加“采样覆盖未重新执行”。矛盾状态（例如只检查 0/100 个样本却标记未发现反例）被拒绝。缩减重算验证每步输入、原策略、失败类别、规模与单调下降条件，保存后把最小性标为 `reduced`，避免把证据重放等同于再次完成局部最小性搜索。
- 回归重新计算每行的前后结果及变化类型。图中“存在路径但局部策略陷入死路”的零数值占位不能被当作最优路径。默认纳入最多 20 个去重、同领域、经复核的已保存反例，包括旧修订；支持 `includeHistory:false`。原实例 + 最多 20 个历史实例 + 最多 100 个保留样本，共至多 121 行。
- 搜索、缩减与回归在 worker 中运行；同时运行 1 个任务，运行中加排队共至多 8 个，超额返回 429。每个 worker 限时 45 秒并设置 V8 内存限制。取消、超时、异常退出、服务重启有独立失败状态，不能解释为“没有反例”。完成前刷新最后一条进度，避免早期发现反例后仍显示 0。
- HTTP 请求上限为 16 MiB，持久化实验额外预留 4 KiB 包装空间，保证正常导出的包可以直接重新导入。每个实验最多 200 个修订；超限前拒绝写入并保留已有数据。此处没有采用原来的 4 MiB 上限，因为实际合法的 121 行图回归已超过该大小。
- 静态资源只来自显式构建目录，关闭目录列表并拒绝点文件。独立 HTML 报告转义所有用户内容，设置严格 CSP；包含输入、策略、真实执行轨迹、版本清单和结论边界。

## AI 边界

AI 地址、模型、密钥都必须配置，未配置返回 503。模型只提出受限策略或解释程序已经算出的事实；未通过契约校验的输出不会应用到实验。不存在伪装成真实模型的离线回答。

每次会话最多 100 次请求，单次最多 30 秒、输出预算 1800 token、响应体 100000 字节，同时只允许一个请求。错误信息不回显上游正文；密钥被上游意外回显时会替换为 `[redacted]`。测试使用虚构占位密钥和 mock fetch，从未读取真实 `.env`。

2026-11-15 检查了 [DeepSeek 官方 Chat Completions 文档](https://api-docs.deepseek.com/api/create-chat-completion/)。官方接口默认启用 thinking；本应用的受限 JSON 任务对 `api.deepseek.com` 明确发送 `thinking:{type:'disabled'}`，避免短输出预算被思考内容占用。其他兼容服务不接收这一专有参数。真实官方调用的独立验证由主开发任务执行；其结果与 mock 测试分开记录。

## 实际验证

命令：在项目目录 dot-source `scripts/env.ps1` 后运行 `pnpm exec vitest run tests/server.test.ts`。

最后一轮结果：**28/28 测试通过**，测试时长约 3 秒。覆盖：

- 三领域目录、确定性评估、独立见证、合法最大值 100000、恶意算式、重复 ID、错领域、未知字段及 16 MiB 请求上限。
- Host/Origin、D 盘数据库约束；真实 HTTP 监听及 `@fastify/static@10.1.11` 构建资源、点文件、路径穿越和目录列表检查。
- SQLite 重启持久化、修订历史、参数化存储、CRUD、版本快照重算、旧实验包兼容。
- 稳定校验和、篡改检测、执行器版本检查、有效校验和下的伪造结果重算、报告 HTML 注入转义。
- 搜索状态一致性；图死路回归；伪装成缩减的纯数组重排被拒绝。
- **真实 worker** 搜索 → 缩减 → 保留样本回归 → 保存 → 导出 → 导入；最后进度、排队上限、取消、超时、重启中断。
- 已保存修订的历史回归、去重、20 个历史输入上限及显式关闭历史。
- **实际 121 行、超过 4 MiB 的图回归**完整保存、导出、导入及轨迹一致性。固定生成种子 921，回归种子 932。
- AI 未配置、成功契约、令牌统计、官方专有参数、恶意模型输出、伪造解释输入、认证失败、无效 JSON、超大响应、密钥脱敏和并发限额。

独立引擎审查发现并复现了五个边界问题：Zod 重复 `.max` 导致合法大值被误拒、4 MiB 不能容纳最大合法回归、早停搜索进度滞后、纯重排被误认缩减、缩减步骤上限与 4000 次检查预算不一致。修复与回归测试已经纳入以上结果。

同轮运行 `pnpm exec tsc --noEmit`：后端和本测试文件无类型错误；唯一报错是 UI Agent 当时尚未写入的 `src/app/App`，因此这里没有把全项目类型检查记录为通过。主任务将在前端完成后再次验收。

## 明确限制

- 本地个人应用，不是多租户托管服务；没有跨设备身份系统。
- 随机搜索和保留样本回归不提供普遍正确性证明。保存的搜索统计是历史记录；经重新验证的实例及结果才是可重放证据。
- 单实验包 16 MiB、200 个修订、任务限时及 20 个历史输入属于明确资源边界，超限时拒绝或终止而不伪造成功。
- worker 隔离用于响应性和资源管理，不能作为任意代码的安全沙箱；应用从不执行用户或模型生成的通用代码。
