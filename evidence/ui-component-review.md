# 双轨轨迹组件复核

2026-11-15，独立检查并修复 `src/app/components/TraceCanvas.tsx`。本记录验证的是独立组件 harness，不代表完整应用端到端验收。

## 发现与修复

- 原来的 `x/maxX`、`y/maxY` 投影会把合法负坐标画到 SVG 外。改为分别使用坐标最小值和最大值归一化；所有坐标相同的轴居中显示，避免零分母。
- 拖动极值节点时，坐标边界随每一帧改变会让其他节点跳动。现在一次手势固定投影，结束后保留该视口；外部输入编辑再重新适配。逆变换采用 SVG screen CTM，正确处理 SVG 比例留白；拖动和方向键移动均保持合法坐标边界。
- 图的节点及边共享双轨悬停/焦点。键值区分 `node:` 和 `edge:`，即使节点与边使用相同 ID 也不会误联动。SVG 容器采用 group，内部对象有名称、焦点与按钮键盘行为；Enter/Space 比较对象，Escape 清除联动，编辑器节点还可用方向键移动。
- SVG 箭头使用组件唯一 ID，避免编辑器和两条轨迹的定义相互覆盖。
- 参照说明区分“等待计算”“独立核验未通过”“目标不可达”“参照计算未完成”和“独立核验的最优结果”，避免未运行时就宣称完成验证。

新 `hovered` / `setHovered` 属性为可选，已有 GraphPlot 调用兼容。主 App 和 CSS 未在本次组件修改中编辑；图对象 `.hovered` 样式由 UI 负责人接入。

## 实际测试

运行 `pnpm exec vitest run tests/trace-canvas.test.ts`：**6/6 通过**。覆盖负坐标极值、退化坐标轴、固定投影与逆变换、参照文案、双轨同对象联动、节点/边 ID 重叠、可访问对象及唯一 marker ID。

随后使用已有 esbuild 0.28.2 打包 D 盘 `.runtime/trace-canvas-harness.tsx`，通过已有 `@playwright/test` 的 Chromium 运行 `.runtime/verify-trace-canvas.mjs`；没有安装额外依赖。harness 使用 React StrictMode 和受控状态，SVG 刻意设置不同于 viewBox 的宽高比例，以测试留白下的坐标转换。

真实浏览器 **8 项行为检查通过**，`pageerror` 为 0：

1. 悬停节点使双轨同节点高亮。
2. 同 ID 的边不会误高亮为节点。
3. Enter / Space / Escape 实际触发比较与清除。
4. 边的键盘焦点使双轨同边高亮。
5. 拖动极值节点期间，未拖动节点的屏幕坐标保持不变。
6. SVG 比例留白下，拖动目标准确跟随指针，屏幕位置误差小于 1 px。
7. 松开指针后，视口不发生重新缩放跳动。
8. 方向键改变目标节点坐标，其他节点数据不变。
