# 全种子研究与自产检查点库

首页的研究库读取公开记录 `evidence/025-stage3-study-results.json`，展示预登记的四个条件、五个训练种子共 20 行。按登记顺序显示，不按成绩排序，也不自动选最好种子。某条计算完成表示执行完该预算，不等于已经学会任务；成绩差、失败、缺失和不能导入的检查点均保留。

## 结果来源和范围

四个条件为 `ppo_reference`、`ppo_large_step`、`sac_reuse1`、`sac_reuse4`；种子为 `11/23/37/53/71`。预算、网络与评价协议来自结果文件内的登记协议，缺少结果时仍可显示 `docs/STAGE3_STUDY.json` 中的登记预算，但不填入推测成绩。

每行的初始与最终平均距离、最后 32 步距离、累计回报、距离小于 0.04m 的评价步占比、交互数、更新数和实际耗时，直接读取公开 `summary[condition].per_seed`。完成行必须与同条件同种子的原始运行计数对应。组内中位数及四分位数读取同一公开摘要。接口不把全部原始曲线和评估回合发给首页；详细数据仍在公开结果文件。

研究只覆盖固定目标 `[0.45,0.12,0.45]` m 和五个评价初始状态种子 `701–705`，采用冻结的 `tanh(mean)*physical_scale` 动作策略。评价步占比不是跨任务成功率，也不支持新目标、真实硬件或教育效果结论。五个训练种子为重复单位，不把各评价回合作为独立训练策略。PPO/SAC交互与计算预算不同；并发开发影响观测耗时，不据此形成隔离性能排名。正式结果、全曲线与局限由 Stage3 研究报告记录，本说明不预先写成绩。

## 本地可用性与导入

开发环境的固定目录为 `.runtime/stage3-study/<condition>-<seed>/final.pgz`。离线包的固定目录为 `examples/study/<condition>-<seed>/final.pgz`。存在 `examples/study` 时优先使用它，包内文件缺失或损坏不会悄悄退回开发目录。浏览器不能提供任意路径。所有解析后的路径必须留在配置的 D 盘项目边界内。

只有原始运行明确为 `completed`、摘要指标齐全且有限、达到登记交互预算、计数对应、检查点存在且 SHA256 与原记录一致，导入按钮才可用。缺少文件、坏哈希、不一致摘要及未完成结果会显示明确原因。哈希只证明与记录的字节一致，不等于科学结论正确。

用户点击后，服务端重新读取并校验哈希，运行原有 JSON + Safetensors 安全解码与 `Learner.from_state`。还会核对算法、训练种子、网络、登记条件超参数和原始交互/更新计数，再建立独立的新实验。新实验包含原始网络、优化器、RNG、环境与回放/rollout状态；不在导入时训练，不覆盖源文件或其他实验。

新实验的 `intervention` 记录 `reference_study_import`、条件、种子、检查点 SHA256、完整公开报告 SHA256、原始计数与来源。此后用户可以检查、运行真实前向、从现有批次执行显式反事实更新、重新评价或继续训练，遵守原本的 on/off-policy 语义。

## 接口和集成

| 接口 | 行为 |
|---|---|
| `GET /api/studies/reference` | 紧凑的全部20行、组摘要、登记预算、范围与可用性。缺失/坏报告不会伪造结果。 |
| `POST /api/studies/reference/import` | `{condition:"ppo_reference",seed:11}`，用户明确点击后导入为新实验，返回201 `{experiment,source}`。不接受额外path或任意条件/种子。 |

后端调用 `install_study_catalog(app, repository)`，放在前端 StaticFiles 挂载之前。该目录服务没有独立任务或常驻网络资源，无需增加关闭钩子。React `StudyLibrary` 接受 `onOpen(experimentId)`，在导入成功后交给主工作台打开新实验。成绩表保留表头、标题和可聚焦的横向滚动区域，窄屏不挤掉数值。

## 实际验证边界

`tests/test_study_catalog.py` 是不模拟服务/物理/学习内核的本地路由测试，使用明确标记的测试专用小网络与六次真实交互。它们不属于正式20次研究。测试核对20行保留、真实失败/缺失显示、摘要数值、只导入匹配状态、不训练/不覆盖、包优先、坏哈希、匹配哈希下的无效包/错误种子/错误计数，以及任意路径和未知字段拒绝。正式检查点的科学复现和浏览器闭环由主阶段另行验证。
